AI Playgrounds

AI Playgrounds is a suite of 15 multilingual, offline-ready learner labs that make AI mechanisms inspectable in ordinary browsers. The current release spans 13 Foundations/course-track mechanisms and two Modern AI extensions, with short assignable inquiry work and a deterministic verification boundary built into the product.

Current product

Mechanism-first labs across the AI curriculum

The catalogue covers search and optimization, logical agents and SAT, probabilistic reasoning, supervised and unsupervised learning, neural networks, computer vision, reinforcement learning, adversarial search, Transformer language modeling, and agent tool-use/runtime protocols.

Inspectable mechanisms

Each lab centers one bounded mechanism and connects learner controls to visual state, text-equivalent explanation, scenarios, teacher guidance, and fidelity disclosures where appropriate.

Portable architecture

The original twelve applets remain standalone HTML. Labs 13–15 are generated deterministically into the public artifact and remain self-contained offline HTML after generation. Learner use requires no account, backend, package manager, or hosted model.

Four-locale learner boundary

All 15 labs and all 15 Quick Assigns support English, Simplified Chinese, Vietnamese, and Spanish under the tested release paths, including learner-state and response preservation during locale changes.

Deliberately narrower support surfaces

Some educator and support pages remain English/Chinese or English-only. The two current Level-2 Activity Pack canaries are English-only. Four-locale learner support is not a claim that the entire website or every teaching resource is available in four languages.

Pedagogy layer

From open exploration to short assignable inquiry

Every lab now has one stable Level-1 Quick Assign, designed for approximately 10–15 minutes and routed through the applet's existing mechanism rather than a parallel worksheet simulation.

  1. Predict
  2. Manipulate or run
  3. Observe
  4. Explain
  5. Transfer

Level 1 · Quick Assigns

Fifteen permanent activity IDs give teachers canonical classroom links. Learners record mechanism-specific predictions, evidence, explanations, and transfer responses inside local browser surfaces that can be copied or printed.

Level 2 · Activity Pack canaries

Two longer pilots, NN-1 and CNN-1, extend the same inquiry spine across connected experiments. They are evidence for the resource architecture, not a claim that every lab already has a longer Activity Pack.

v1.8.1 parity work

The three newer lab surfaces reached the established learner depth

Transformer Language Modeling, Agent Tool Use and Context Protocols, and Minimax/Alpha-Beta already shared the release shell, yet their learner sequence remained thinner than the first twelve applets. v1.8.1 closes that bounded gap.

Scenario-led instruction

Each of the three labs now includes one featured experiment, five predict–run–explain scenarios, a terminology primer, a step-by-step mechanism explanation, teacher prompts, and misconceptions in all four learner locales.

One mechanism state

Scenario actions drive each lab's native controls. The Transformer, agent-runtime, and game-tree mechanisms were not replaced, and the teaching layer does not introduce a second simulation state.

Shared interaction shell

Share, Embed, JSON, and Reset use the established action-row pattern. Quick Assign state capture is learner-triggered, and accessibility guidance points to each lab's native text state rather than an always-open duplicate mirror.

Dark-theme legibility

The parity pass adds explicit contrast treatment for headings and actions, Transformer mask and warning surfaces, agent semantic states, and Minimax controls, traces, comparisons, tree nodes, and pruning states.

Verification

A layered release boundary, not one test count

The original 45-test algorithm harness remains an inherited layer. Current assurance also includes lab-specific references, cross-runtime parity, localization and state contracts, deterministic composition, and browser behavior. For that reason, the historical 45/63 pair is retained as provenance rather than reused as the present release total.

  1. Algorithm and reference checksDeterministic regression, independent references where applicable, cross-runtime parity, and targeted gates for later labs and opt-in mechanism modes.
  2. Deterministic final compositionThe exact v1.8.1 artifact is built twice and all 58 deployed-file hashes are compared. Final JSON blocks are parsed and executable inline scripts are compiled after wrapper composition.
  3. Browser and HCI state transitionsAutomated checks exercise responsive containment, four-locale response preservation, the fifteen scenario actions across the three parity labs, shared header geometry, dark-theme contrast, canonical state behavior, embed mode, and recovery paths.
  4. Release and provenance controlsMetadata, public composition, release tag, source revision, and deployment sequencing are checked so the published claim boundary identifies the verified artifact.

Evidence boundary

What the release evidence supports

Supported under tested conditions

Software behavior, deterministic composition, selected algorithm/reference relations, release integrity, supported-path locale and state preservation, responsive interaction behavior, and representative contrast measurements.

Not established by software checks

Measured learning gains, classroom adoption, comparative educational effectiveness, universal learner preference, translation naturalness for every learner group, accessibility conformance, equitable access, or production-system equivalence.

The applets are inspectable teaching implementations. Their fidelity notes define which mechanism is represented and where the model stops; release verification does not convert a bounded teaching model into a claim about a full production solver, frontier language model, deployed agent, or hardware-performance benchmark.

Privacy and reuse

Local learner work, explicit analytics limits

AI Playgrounds has no student accounts, submission backend, database, or student-upload endpoint. Built-in packet, Quick Assign, and Activity Pack responses remain in the learner's browser until copied, printed, exported, cleared, or otherwise handled by the learner or teacher.

The canonical site uses privacy-minimized aggregate analytics for canonical page/event identifiers and allow-listed campaign attribution. It excludes learner answers, experiment values, query-state payloads, names, grades, and general referrer URLs. Global Privacy Control, Do Not Track, local opt-out, offline copies, localhost, and non-canonical mirrors disable project analytics.
